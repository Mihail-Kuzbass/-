# TrafficSignalStudio — Windows prototype, iteration 0.2

Настольное приложение Python/PySide6 для подготовки светофорных сценариев. Архив расширяет исходный проект; это **не сертифицированная профессиональная транспортная модель**.

## Реализовано в этой итерации

- Интерфейс Windows на PySide6 с вкладками поиска 2ГИС, условной схемы, фаз, параметров потока и отчёта.
- Поиск объектов через 2ГИС Places API при наличии действующего ключа с доступом к соответствующему API.
- Отдельный импорт дорожных линий OpenStreetMap через Overpass API по ограниченному прямоугольнику, открытие и сохранение GeoJSON.
- Проверка базовых ограничений фаз и сохранение/загрузка плана фаз в JSON через модуль `SignalPlan`.
- Улучшенная пошаговая агрегированная очередь для двух конфликтующих направлений, воспроизводимая по seed, отчёт с остаточными очередями и задержкой.
- Дополнительная интерактивная вкладка: отдельный спрос по каждой полосе и манёвру (прямо/налево/направо), интенсивность пешеходов по переходам, анимированная схема, запуск/пауза/сброс и отдельный отчёт.
- Назначение обслуживаемых движений в фазах через идентификаторы, например `Север:*`, `Юг:*`, `Пешеходы:Север`; старые планы JSON продолжают загружаться.
- Автотесты ключевых правил плана, GeoJSON и повторяемости модели.
- Скрипт сборки Windows `build_windows.bat`.

## Чего пока нет

- Импорт дорожной топологии и полос из 2ГИС. Places API предназначен для каталожного поиска и сам по себе не предоставляет готовую транспортную сеть.
- Отображение импортированных дорог в редакторе, автоматическое определение полос/поворотов/конфликтов и привязка к реальной геометрии перекрёстка.
- Полноценная калиброванная микросимуляция отдельных траекторий автомобилей и пешеходов, перестроений, геометрических конфликтов, общественного транспорта, приоритетов и координации нескольких перекрёстков. Новая анимация является наглядной условной визуализацией, а не точной траекторной моделью.
- Автоматическая оптимизация сигналов, нормативная проверка по конкретным стандартам и калибровка по полевым данным.
- Проверка работоспособности на Windows в этой среде. Готовый EXE не включён в архив: сборку необходимо выполнить на Windows.

## Установка и запуск в Windows 10/11 x64

1. Установите Python 3.11+ с python.org и отметьте добавление Python в PATH.
2. Распакуйте архив в папку без кириллических символов в пути (рекомендуется).
3. Запустите `build_windows.bat`. Скрипт создаст виртуальное окружение, установит зависимости, выполнит тесты и соберёт приложение.
4. После успешной сборки запускайте `dist\TrafficSignalStudio\TrafficSignalStudio.exe`. Это сборка в виде каталога, поэтому переносить нужно весь каталог `dist\TrafficSignalStudio`.

Ручной запуск:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m app.main
```

## 2ГИС

Вкладка «2ГИС / импорт» поддерживает поиск объектов через Places API. Вставьте ключ в поле и сохраните его локально. Ключ хранится в `%USERPROFILE%\.traffic_signal_studio\settings.json`; не публикуйте файл настроек и не включайте личный ключ в общий архив. Условия, квоты и доступность продуктов проверяйте в официальной документации 2ГИС: https://docs.2gis.com/.

## Импорт геометрии дорог

Кнопка «Импортировать дороги OSM вокруг точки» запрашивает дорожные линии OpenStreetMap через публичный Overpass API в небольшой области вокруг введённых координат. Импорт не гарантирован: публичные серверы могут быть перегружены или ограничивать запросы. В качестве альтернативы можно открыть локальный GeoJSON. Данные сохраняются как GeoJSON FeatureCollection.

OSM — отдельный источник, а не 2ГИС. Соблюдайте требования OpenStreetMap attribution/ODbL и условия источника. Геометрия линий не равна полноценной сети для транспортного моделирования.

## Валидация, выполненная при подготовке архива

- `python -m pytest -q` — базовые тесты логики.
- GitHub Actions выполняет сборку Windows и проверку запуска GUI в режиме offscreen. Успешная упаковка сама по себе не заменяет ручную проверку интерфейса на Windows.

## Редактор перекрёстка и светофорных фаз

- На вкладке «Схема» задаётся число полос для каждого из четырёх подходов (1–8); схема обновляется сразу.
- Схему можно сохранить и загрузить в формате JSON.
- На вкладке «Светофорная программа» можно добавлять и удалять фазы, редактировать название и длительность зелёного, зелёного мигающего, жёлтого, красного и межфазного интервала.
- Светофорный план поддерживает до 32 фаз и сохраняется в JSON. Загрузка старых планов версии 1 поддерживается.
- Длина цикла считается как сумма всех интервалов каждой фазы.

Ограничение текущей версии: схема перекрёстка пока условная, а агрегированная модель транспортного потока обслуживает только первые два направления. Дополнительные фазы влияют на расчётную длину цикла, но ещё не имеют самостоятельных потоков/полос в симуляции. Время красного внутри записи фазы — параметр схемы плана; для инженерного применения необходимо проверить, что фазные интервалы описывают реальную работу контроллера и не создают конфликтующих разрешающих сигналов.


## Интерактивная модель (итерация 0.3)

- Вкладка «Интерактивная модель» содержит строки спроса для каждой комбинации подхода, полосы и манёвра. Кнопка «Сформировать строки по числу полос» обновляет список после изменения числа полос на вкладке «Схема» и сохраняет введённые значения для существующих строк.
- Интенсивность транспорта задаётся в авт./ч, интенсивность пешеходов — в чел./ч для каждого из четырёх переходов.
- В последнем столбце таблицы фаз указываются назначения через запятую. `Север:*` назначает все транспортные движения северного подхода, `Пешеходы:Север` — северный переход. Для каждой фазы можно задать собственный набор разрешённых движений.
- Если в плане не задано ни одного назначения, детальная модель применяет демонстрационное правило: первая фаза обслуживает Север/Юг, вторая — Восток/Запад. Пешеходные переходы необходимо назначить явно.
- Визуализация показывает условные маркеры автомобилей и пешеходов; она не строит физически точные траектории и не выполняет автоматическую проверку конфликтов. Результаты предназначены для изучения сценариев, а не как единственное основание для инженерного решения.
